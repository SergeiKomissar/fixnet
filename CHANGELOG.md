# CHANGELOG — fixnet / netinfo / netlib

Формат: фазы развития «швейцарского ножа» (netinfo наблюдает, fixnet чинит, netlib —
общий слой). Даты приблизительные; канонический исходник — этот репозиторий.

## Фаза 13.3 — `--why` ловит регион-блок, отданный как HTTP 200
- Региональная блокировка часто приходит СТРАНИЦЕЙ-ЗАГЛУШКОЙ с кодом 200 (Claude
  «App unavailable in region», и т.п.), а не 403/451 — раньше `--why` говорил «отвечает
  нормально». Теперь для HTML/JSON дочитываем до 16 КБ тела (файлы не трогаем) и ловим
  регион-маркеры через ai_classify → класс `blockpage`: «Содержимое: страница-заглушка»
  + вердикт со страной выхода («выходишь из «Россия» (VPN выключен) — включи VPN»).
- Новый маркер `region_restricted`; дисклеймер честно про «HTML читаем до 16 КБ на маркеры».
- CURL ≠ БРАУЗЕР: страницы за входом/Cloudflare (напр. claude.ai/new) отдают пробе 403
  «Just a moment…», хотя в залогиненном браузере открываются. Отделили Cloudflare-ЧЕЛЛЕНДЖ
  (`cloudflare_challenge`, браузер проходит — НЕ «смени сервер») от жёсткого блока (1020/
  «you have been blocked» — IP плохой). Формулировки в --why и --ai дифференцированы.

## Фаза 13.2 — доступ к `--why` без Терминала
- Кнопка `~/Desktop/why.command` (канон `why.command`): берёт ссылку из буфера обмена
  или просит вставить → `netinfo --why`; ПОСЛЕ проверки предлагает проверить ещё ссылку
  (цикл), а не только закрыть. read-only, sudo не нужен. Фирменная иконка (зелёный Wi-Fi + «?»).
- Клавиша `u` в меню netinfo: ввод ссылки → `why_report` (та же логика, без дублирования).
- `--why` теперь печатает СТРАНУ ВЫХОДА в шапке («Откуда стучимся: Страна, Город · IP»):
  для 403/451 принципиально — отказ из РФ/КНР и из ЕС значит разное. + VPN вкл/выкл явно.
- Полировка формулировок --why: HTTP 451 → «юридическое/политическое ограничение» (без
  «не поддерживает регион»); VPN-подсказки с заглавной; при потерях пакетов отдельный
  хвост «есть потери пакетов — …могут рваться» вместо «большие загрузки».

## Фаза 13 — `netinfo --why URL` (на каком слое не открывается ресурс)
- Послойная диагностика конкретного URL: контроль «сеть жива» → DNS(+DoH) → TCP → TLS →
  HTTP(код+тело), один `curl --range 0-0` (1 байт, файл не качаем). Отделяет «у меня сеть
  лежит» от «именно этот ресурс не идёт».
- Классы: local_network / dns_problem / dns_doh_only / tcp_blocked / tls_blocked /
  http_forbidden (регион/antibot через ai_classify) / auth_required / html_instead_of_file /
  not_found / rate_limited / server_error / redirect_loop / slow_or_timeout / ok.
- Человеческий вывод: послойные «Проверки» + «Вывод» (слой отказа + что попробовать).
  Честно: называем СЛОЙ, не «причину блокировки»; без «РКН/DPI»; IP-литерал не считаем
  DNS-проблемой; dns_problem — «либо домена нет, либо DNS сети фильтрует».
- read-only: без ключей, без записи state, систему не меняем; VPN — только контекст +
  подсказка «включи VPN/смени сервер и повтори» (без авто-сравнения). JSON — отложен (13.1).

## Фаза 11 — улучшенный `--scan` (панель, не авто-переключатель)
- ★ «сохранена» — метка известных macOS сетей (known-networks.plist, root-only). Нет ★
  ≠ «не сохранена» (без root список не виден). Текст «★ сохранена», не «можно подключиться».
- Дубль-SSID: один SSID на 2.4/5/6 ГГц. Если ты на 2.4, а сеть видна на 5 ГГц →
  подсказка «для VPN/видео 5 ГГц обычно лучше; переподключиться вручную». Текущий
  диапазон берётся авторитетно из «Current Network Information».
- Мягкое ранжирование по score (в UI без баллов): RSSI доминирует, band — лёгкий
  тай-брейк (исправлен баг: раньше 5 ГГц/−82 вставал выше 2.4/−45). Открытая — мягкий
  минус, сохранённая — плюс. Никаких «Лучшая сеть: X», таблица + подсказки.
- Колонка «примечание» (← вы здесь / ★ сохранена). Не подключаемся, сеть не выбираем.
- Отложено (11.1, только при достоверных данных): Noise / Channel Utilization — их
  обычно меряют по текущему каналу, не по соседней сети.

- 10.3 DNS self-heal по возрасту бэкапа: свежий (<6 ч) → [Y/n], старый → [y/N];

- Отклонено из ревью: вынос PROBE_IP в netlib (дублирование намеренное), json-ошибка в

## Санитария — LC_ALL=C точечно (укрепление парсинга, без нового поведения)
- `LC_ALL=C` добавлен ТОЧЕЧНО к командам, чей вывод парсится как ДЕСЯТИЧНЫЕ числа
  (реальный риск запятой-локали `LC_NUMERIC`): `ping`/`ping6` (RTT), `avg_rtt`,
  `curl -w` speed_download/speed_upload/time_appconnect.
- Плюс дешёвая страховка на многополевые: `wdutil info`, `system_profiler`, `scutil --dns`.
- СОЗНАТЕЛЬНО НЕ трогали `route`/`ifconfig`/`networksetup` — они извлекаются по английским
  токенам (`interface:`, `gateway:`, `inet`, `mtu`), локаль их не меняет → эффект нулевой,
  а правок было бы 15+ шума. НЕ делаем глобальный `export LC_ALL=C` (сломал бы UTF-8/
  кириллицу/эмодзи/сортировку в человеческом выводе и JSON). Поведение и вывод не менялись.

## Фаза 9 — IPv6-фолбэк только для строки задержки
- Узкая цель: не терять метрику RTT, когда IPv4-ping не дал результат, а интернет жив
  (NAT64/мобильные/роуминг). НЕ меняет общий verdict (он по HTTPS), не делает отдельную
  IPv6-диагностику.
- Если IPv4 RTT не получен, но HTTPS/NET живы → `ping6` по якорям 2606:4700:4700::1111
  → 2001:4860:4860::8888. Парсер тот же (формат строки ping6 идентичен IPv4).
- Вывод: «задержка: 74 мс — хорошо (IPv6)»; --tech показывает, что измерено по IPv6;
  JSON: `quality.latency_probe` = ipv4|ipv6|null.
- Без IPv6-маршрута ping6 возвращается мгновенно (~0.02 c) — зависания нет. Не пишем
  «IPv4 сломан / IPv6 работает» (один якорь — слишком сильный вывод).

## Фаза 8 — DoH-фолбэк для DNS (убирает ложные тревоги «DNS не работает»)
- Когда обычный UDP-53 резолвер молчит (dig падает), но система на шифрованном DNS/
  Private Relay и браузер резолвит — раньше был ложный «DNS не работает → fixnet --dns».
- Добавлена DoH-проба (только при DNS=0 и наличии связи): `1.1.1.1/dns-query` → фолбэк
  `dns.google/resolve`. Успех = `Status:0` + Answer с data.
- Три честных исхода: UDP-53 жив / UDP-53 молчит, но DoH резолвит / не резолвится вовсе.
  При «DoH резолвит + сайты открываются» — верхний вердикт 🟢, строка DNS 🟡, ремонт НЕ
  зовётся. При «DoH резолвит, но сайты не открываются» — `sudo fixnet --dns`. При «оба
  мертвы» — честно «проблема глубже, fixnet --dns может не помочь».
- ИНВАРИАНТ: DoH-успех ≠ «системный DNS работает» (приложения могут не идти через DoH).
- JSON: блок `dns:{udp53,doh}`; коды `dns_doh_only` / `dns_unresolvable`.

## Фаза 7.4 — отличаем anti-bot блок IP от регионального отказа
- VPN-выходы у владельца — дата-центры (EDIS/Gigahost/UFO Hosting), их IP часто в
  чёрных списках Cloudflare. Тогда сервис отдаёт не региональный отказ, а anti-bot
  страницу («Just a moment…», «Attention Required!», «error code: 1020»).
- Эти ответы (плюс «you have been blocked», «access denied») теперь отдельная
  подкатегория blocked → «🔴 антибот-защита (IP в чёрном списке)» с действием
  «смени СЕРВЕР/IP (лучше не дата-центр)» — вместо «смени страну VPN».
- Это разный диагноз: региональный отказ лечится сменой страны, anti-bot — сменой
  сервера/IP. JSON: block_reason = cloudflare_antibot/cloudflare_1020/blocked_page/
  access_denied (точная причина в массиве ai[]).

## Фаза 7.3 — точный маркер регион-отказа Anthropic
- Заземлено вживую: Claude из РФ отвечает 403 `{"type":"forbidden","message":"Request
  not allowed"}` (в рабочем регионе — 405). Добавлен маркер `request not allowed` →
  Claude из РФ теперь «🔴 региональный отказ» (точная причина `request_not_allowed`),
  а не общий «доступ запрещён (403)». Рабочий 405 «Method Not Allowed» не задевается.
- RU-кейс подтверждён целиком: OpenAI 🔴 регион, Claude 🔴 регион, Gemini 🟡 не
  подтверждён, Z.AI 🟢/🟠 проходит.

## Фаза 7.2 — 4-й класс `unconfirmed` (честный предел keyless-проверки)
- Живой кейс РФ вскрыл false-negative: Claude и Gemini из РФ отвечали 403, но тело без
  региональных маркеров → ошибочно показывались «🟢 сеть проходит», хотя НЕ работали.
- Введён 4-й класс: `network_ok` / `blocked` / **`unconfirmed`** / `unreachable`.
  - «Голый» 403 (forbidden без «нужен ключ») → `blocked` 🔴 — надёжно ловит Claude из РФ
    (в рабочем регионе он отвечает 405, а 403 для него аномален).
  - 403 с «нужен ключ» (Gemini) → `unconfirmed` 🟡 «доступ не подтверждён»: без ключа
    ответ из РФ и из рабочего региона байт-в-байт одинаков — отличить нельзя в принципе.
- JSON: `verdict` теперь network_ok|blocked|unconfirmed|unreachable; `block_reason`
  = `needs_key` для unconfirmed; новый код `ai_unconfirmed`.
- Это честный предел: подтвердить продуктовый доступ к модели сможет лишь будущий
  `--ai-auth` (с ключом). Keyless-режим не красит сомнительный 403 ни зелёным, ни красным.

## Фаза 7.1 — отличаем «сеть проходит» от «региональный отказ»
- Исправлен изъян семантики Фазы 7: TLS-handshake завершается и из заблокированного
  региона (CDN отвечает), а сервер возвращает 403 «регион не поддерживается» — старая
  логика «любой HTTP-код = доступен» это проглатывала (ложное «доступен» из РФ).
- Теперь читаем ТЕЛО ответа и классифицируем по трём классам:
  `network_ok` / `blocked` (региональный/политический отказ) / `unreachable`.
- Код 403 сам по себе НЕ блок (Gemini отдаёт 403 «нет ключа» и в рабочем регионе) —
  блок определяем по маркерам в теле (`unsupported_country`, «location is not
  supported», «error code: 1020», …) и коду 451.
- Терминология: «сеть проходит» вместо «доступен» (не обещаем рабочую модель);
  «региональный отказ», не «РКН/DPI/госблок» (видим лишь отказ сервиса/CDN/политики).
- JSON: `reachable`→`network_reachable`; добавлены `verdict`(network_ok|blocked|
  unreachable) и `block_reason`. Коды: `ai_region_blocked`, `ai_partial_blocked`
  (вместо `ai_partial_unreachable`).
- Заголовок блока: «AI API-домены». Клавиша `i` проверяет полный набор (`--ai all`).

## Фаза 7 — `netinfo --ai` (доступность нейросетей через VPN)
- Проверка доступности AI-сервисов по времени TLS-handshake (не ICMP — CDN врёт).
  Любой HTTP-код = достижим; таймаут/`000` = не достучались. Без ключей и промптов.
- Команды: `--ai` (OpenAI+Claude), `--ai all` (+Gemini+Z.AI), `--ai list`, `--no-ai`.
  Клавиша `i` в меню.
- Компактный блок «Нейросети:» в основном выводе — по умолчанию при активном VPN,
  опт-аут `--no-ai`. `--ai` работает всегда (без VPN — «проверяю напрямую»).
- Пороги: ≤400 🟢 good / 400–800 🟡 degraded / >800 🟠 slow / нет связи 🔴 unreachable.
  Каждый сервис отдельно (не усредняем).
- WORK стал AI-aware: при активном VPN итог про то, доступны ли нужные сервисы;
  при недоступности — предметный совет «смени страну/сервер VPN».
- JSON: блок `ai[]` (name, url_host, reachable, http_code, latency_ms, dns_ms,
  verdict, error) — только если проверка запускалась; коды `ai_checked`,
  `ai_unreachable`, `ai_partial_unreachable`, `ai_high_latency`.
- Конфиг `~/Library/Application Support/netinfo/ai-targets` (TSV `Имя<TAB>URL`) —
  только данные, без source/eval; только https; битые строки → предупреждение.
- Оговорка: «доступен = TLS-ответ API-домена без ключа», не проверка ключа/модели.

## Мелкие правки рендера
- `country_name`: расширен справочник (BE, UK-алиас к GB, UZ, CN, HK + прежние).
  Человеческий вывод — «Бельгия, Zaventem» вместо «BE, Zaventem». В `--json` добавлено
  поле `exit.country_name` (рендер), машинный код `exit.country` сохранён; неизвестный
  код → `country_name: null` (не дублируем код). Города массово не русифицируем.

## Фаза 6.1 — `netinfo --json` (машиночитаемый контракт)
- Новый флаг `--json`: стабильный API из блоков `status / exit / link / quality /
  vpn / memory / warnings / codes`. Только факты и коды состояний, без человеческих
  фраз (человеческий текст — слой рендера).
- Коды состояний: `open_wifi_with_vpn`, `open_wifi_without_vpn`, `bad_latency`,
  `not_wifi_bottleneck`, `narrow_5ghz_channel`, `many_vpn_traces`.
- Строит python3 (`json.dumps`, `ensure_ascii=False`) — устойчиво к любым SSID
  (пробелы/кавычки/emoji/ANSI-подобные/пустой). `null` для недоступного (rssi без
  root, скорость при `--no-speed`). `provider` — сырой факт (`AS… Org`).
- netlib: `nl_history_recall <ssid> json` → машинный TSV `count\tlast_seen\tlast_q`.
- Тесты: `netinfo --json | python3 -m json.tool` ✅; матрица странных SSID ✅.

## Фаза 6 — link awareness + `netinfo --scan` (соседние Wi-Fi)
- Строка «Подключение» (после VPN-выхода): физический линк — Wi-Fi / раздача с
  телефона по Wi-Fi / iPhone(iPad) по USB / Ethernet — с диапазоном/каналом/шириной
  инлайн. Даже при активном VPN показываем реальную подложку, а не «через utun».
- Раздача с телефона — по подсети Apple `172.20.10.x` + сервисам `iPhone/iPad USB`.
- 5G/LTE СОЗНАТЕЛЬНО не определяем (Mac не видит поколение сотовой) — при раздаче
  честная подсказка «смотри на iPhone».
- `netinfo --scan` (+ клавиша `s` в меню): соседние сети, сигнал/диапазон/защита,
  сортировка по силе; `airport -s` мёртв → `system_profiler`. Сигнал «—» где macOS
  не отдала. Open ⚠; «лучший сигнал» — только среди защищённых. Сам НЕ подключается.
- Открытая Wi-Fi сеть: советы стали **VPN-aware**.
- ИСПРАВЛЕНИЕ смыслового движка (WORK/QLEVEL): «включи VPN» теперь только когда VPN
  реально не активен (был баг: открытая сеть + активный VPN → «включи VPN»).
- VPN-выход спокойнее: «активен — Страна, Город» + нейтральная «Проверка VPN», без
  тревожного «отвалился» (ожидаемую страну инструмент не знает).
- Память: «сеть знакомая — N замеров; прошлый — …».
- `--advice`: при «Wi-Fi хороший, но медленно» — цифры + причины + действия; заметка
  про узкий канал (20 МГц на 5/6 ГГц).

## Фаза 5 — `netinfo --probe` (проба TCP/UDP-выхода для VPN)
- TCP-connect доказуем, UDP — нет: меряем только через рефлекторы (DNS/NTP/STUN).
- Не называем порт «заблокированным», не утверждаем «DPI». netinfo-only.

## Фаза 4 — MTU path discovery (`netinfo --mtu` + `fixnet --mtu`)
- Зонд path MTU (DF-ping, бинарный поиск); персистентная смена MTU с откатом.

## Фаза 3 — `fixnet --wifi-reset` (залипшая Wi-Fi-сессия)
- Передёргивание радио (off→on→DHCP) со снимком «до/после»; деструктивно, дефолт N.

## Фаза 2 — `fixnet --dns` (аварийная подмена DNS)
- Бэкап/откат/self-heal; не трогает Tailscale CLI.

## Фаза 1 — память + узнавание сети + заход в портал
- netlib (state/history/config), узнавание сети, открытие captive-портала.

## База
- `fixnet` — аварийное восстановление маршрутов/DHCP (10 раундов ревью).
- `netinfo` — человекочитаемый осмотр; вердикт по HTTPS, не ICMP.
- Прогресс-спиннер (общий, в `/dev/tty`), флаги `NL_NO_SPINNER`/`NL_SPINNER_STYLE`.

## Инварианты (не нарушать при доработке)
- netinfo НЕ меняет сеть; меняет только fixnet (root, с откатом: файл-бэкап + self-heal).
- «Не гадать»: нет надёжного источника — молчим (5G/LTE, скрытая незапомненная сеть).
- «Включи VPN» — только при `vpn_active=false`.
- Соседние сети (`--scan`) — read-only, сам не подключается.
- JSON — только факты/коды, человеческий текст не в полях.
